### How signed-in E2E works (and why no test seam)

The emulators run on this machine with Java 21 (`/opt/homebrew/opt/openjdk@21`; the default Java 17 is too old for the current Firestore emulator), so the preferred design was used and **no test-only route or flag was added to the app**:

- **Sign-in**: the test asks the Auth emulator's Google provider for an ID token (`accounts:signInWithIdp`), the browser posts it to the real `POST /api/session` with the app's Origin, and the server mints the httpOnly session cookie with the Admin SDK (`e2e/signed-in/auth.ts`). Each test is a fresh Google user, so tests share no state and run in parallel.
- **Gemini**: `e2e/signed-in/fakeGoogle.mjs` is a scripted Gemini REST server reached through the SDK's own `GOOGLE_GEMINI_BASE_URL`. It answers AI mode by keywords in the latest instruction ("Plan the extras" gives three cards, "Cut decor spend by 20%", "make that 15% instead", "server error" fails), ideas, What-if and enquiry by response schema, and fails plan generation on purpose, so new events take the starter-template path exactly as with no key.
- **Credentials**: the same file serves a fake GCE metadata server (`GCE_METADATA_HOST`), because the Admin SDK's Firestore over REST asks for Application Default Credentials even under the emulator (QA-08). It returns `owner`, the emulator's admin token.
- **Isolation proof**: `tests/unit/e2eIsolation.test.ts` scans `src` for any test switch (`UTSAV_E2E`, fake-model flags, the fake server's env names), asserts `session/route.ts` is the only auth route, and that emulator hosts alone never give the server a database or auth.
- **Known bugs as tests**: each confirmed bug has a test marked `test.fail` / `it.fails` with its ID. They pass while the bug exists and turn red when it is fixed, so the marker gets removed then.
